# 手动部署清单（云服务器）

> 适用：Debian 系 2C2G 云服务器，有域名 + TLS。手动执行，逐步验证。
> 若你**已有完整的 element-skin 部署**，可跳过第 2 步（部署 demo 站），只需部署接收端。

## 0. 前置

- 域名：**共用 element-skin 域名**（如 `union-test.gpa.ac.cn`），接收端挂在 `/wh/` 前缀下；
  - element-skin API：`https://union-test.gpa.ac.cn/skinapi`
  - 接收端：`https://union-test.gpa.ac.cn/wh`
- 服务器已装 Docker + Docker Compose、Python 3、Nginx。

## 1. 同步代码到服务器

```bash
# 在服务器上
mkdir -p /opt/element-skin-webhook-test
# 把本地 element-skin-webhook-test 仓库内容同步到 /opt/element-skin-webhook-test
# （scp / rsync / git clone 均可；注意排除 .venv、receiver.db、config.json）

# 同时同步 element-skin 的 python-sdk（接收端依赖，未发布到 PyPI）
mkdir -p /opt/element-skin
# 把本地 element-skin/python-sdk 目录同步到 /opt/element-skin/python-sdk
# （只需 python-sdk 目录，不需要整个 element-skin 仓库）
```

## 2. 部署 element-skin demo 站

> **已有 element-skin 部署可跳过本节**，直接到第 3 步。只需确认：
> - 后端 API 公网可达（如 `https://union-test.gpa.ac.cn/skinapi`）；
> - `webhook-worker` 服务在运行（docker compose 里已有独立 worker 容器）。

```bash
cd /opt
git clone https://github.com/water2004/element-skin.git
cd element-skin
cp .env.example .env
# 编辑 .env，重点修改：
#   ELEMENT_SKIN_IMAGE=ghcr.io/water2004/element-skin:latest
#   JWT_SECRET=<随机长密钥>
#   IDENTITY_ENCRYPTION_KEY=$(openssl rand -base64 32)   # 生成后长期保存
#   DATABASE_PASSWORD=<随机密码>
#   REDIS_PASSWORD=<随机密码>
#   SERVER_SITE_URL=https://union-test.gpa.ac.cn
#   SERVER_API_URL=https://union-test.gpa.ac.cn/skinapi
#   CORS_ALLOW_ORIGINS=https://union-test.gpa.ac.cn
#   VITE_BASE_PATH=/
#   VITE_API_BASE=/skinapi
docker compose up -d
docker compose ps   # 确认 db/redis/backend/webhook-worker 均 healthy
```

## 3. 安装接收端依赖

```bash
cd /opt/element-skin-webhook-test/receiver
python3 -m venv .venv
# 先安装 element-skin-sdk（未发布到 PyPI，本地安装）
.venv/bin/pip install -e /opt/element-skin/python-sdk
# 再安装其余依赖
.venv/bin/pip install -r requirements.txt
```

## 4. 配置接收端

```bash
cd /opt/element-skin-webhook-test/receiver
cp config.example.json config.json
# 编辑 config.json：
#   - site_api_base: https://union-test.gpa.ac.cn/skinapi
#   - route_prefix: /wh（默认，与 element-skin 共用域名）
#   - endpoints[].signing_secret: 创建应用后填入（见第 6 步）
#   - oauth.client_id / redirect_uri / refresh_token: 应用 A 授权后填入
```

## 5. 安装 systemd 服务 + Nginx

```bash
# systemd
cp /opt/element-skin-webhook-test/deploy/receiver.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now element-skin-receiver
systemctl status element-skin-receiver   # 确认 active

# Nginx（共用域名：/wh/ 转发到接收端，其余走 element-skin）
cp /opt/element-skin-webhook-test/deploy/nginx.conf /etc/nginx/sites-available/element-skin-webhook-test
# 替换域名（或 export DOMAIN_SKIN=union-test.gpa.ac.cn 后跑 setup.sh）
sed -i 's/union-test\.gpa\.ac\.cn/union-test.gpa.ac.cn/g' /etc/nginx/sites-available/element-skin-webhook-test
ln -sf /etc/nginx/sites-available/element-skin-webhook-test /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx

# TLS（Let's Encrypt）
apt install certbot python3-certbot-nginx
certbot --nginx -d union-test.gpa.ac.cn
```

## 6. 创建测试应用（关键步骤）

在**本地**（或服务器）运行：

```bash
# 需要先有管理员账号（在 demo 站注册第一个用户，通常自动为管理员）
cd /opt/element-skin-webhook-test/scripts
.venv/bin/python create_apps.py \
  --base https://union-test.gpa.ac.cn/skinapi \
  --admin-email admin@example.com --admin-password '...' \
  --hooks-base https://union-test.gpa.ac.cn
```

脚本会：
1. 创建应用 A（PlayerWall）与 B（Webhook Probe）；
2. 提交审核并激活；
3. 把 `client_id` / `client_secret` / `signing_secret` 保存到 `scripts/state/apps.json`。

**然后把 `signing_secret` 填入接收端 `config.json`，重启接收端：**

```bash
systemctl restart element-skin-receiver
```

## 7. 授权应用 A

```bash
.venv/bin/python authorize_a.py \
  --base https://union-test.gpa.ac.cn/skinapi \
  --user-email user@example.com --user-password '...'
```

把返回的 `refresh_token` 填入接收端 `config.json` 的 `oauth.refresh_token`，重启接收端。

## 常见问题

| 问题 | 排查 |
| --- | --- |
| 接收端收不到事件 | endpoint URL 是否公网域名、应用是否 active、worker 是否运行、`webhook_deliveries` 表状态 |
| 投递一直 pending | 接收端日志 `journalctl -u element-skin-receiver`、Nginx 访问日志、worker 日志 |
| 验签失败 | `signing_secret` 是否与创建应用时一致（只显示一次，丢失需重建 endpoint） |
| 2C2G 资源不足 | 压测错峰；worker 默认 2 连接保护主站；必要时调低并发 |
